# 动态 HTML／SVG 盲选测试

这是源码仓库中的本地工具，调用当前 CoThink 的 Pi 运行路径。默认两模型分别独立运行，再由第一个模型领导、第二个模型协作。每道题三个尝试；三道题共九个尝试在独立子进程全部就绪后统一放行。

任务文本严格为：

```text
做一个{题目}的动态html界面，svg，不允许联网
```

不会附加尺寸、构图、静态画面、文件格式或禁用 JavaScript 的任务指令。正式 CoThink 的系统提示、工具说明和内部委派消息仍属于被测系统，不能把它们称为三组完全相同。资源隔离设置会与阶段系统提示合并：首答保留主答提示，评审保留评审提示，执行领导与成员使用各自角色提示。

## 首次准备

在本仓库根目录，使用 Node ≥22.19、Git、Docker Desktop。一次性安装开发依赖和独立浏览器：

```sh
npm ci --ignore-scripts
npm exec playwright install chromium
```

这些是工具准备操作。被测模型的工作容器 `network:none`，没有联网搜索工具；预览在独立 Chromium 中阻断外部 HTTP、WebSocket、页面跳转、Service Worker 和 WebRTC。不要把作品从保护性预览中拿到日常浏览器执行后，仍视为同样的离线环境。

生成配置模板，复用 CoThink 最近使用 Team 的前两个模型，不复制认证到配置中：

```sh
node scripts/visual-bench.mjs init --config work/visual-bench/config.json
```

核对 `models[0]` 和 `models[1]`。第一个模型用于单模型组一及 CoThink 主模型，第二个用于单模型组二及 CoThink 副模型。当前版本支持 `openai-completions` API（含 OpenRouter 和 Moonshot）；不把不支持的协议悄悄替换成另一个模型或协议。

配置中的关键字段：

- `sourceHome`：已有 CoThink 认证和目录的位置，仅宿主读取；模型任务看不到原始认证。
- `models`：两个模型的 provider、modelId，以及可选的 thinkingLevel。真实目录与协议参数在 prepare 时读取并保存。支持思考的模型若未指定档位，prepare 会明确冻结为 `high`；显式档位保留。旧轮次和旧记录不回写。
- `limits.maxMinutes`、`maxCalls`、`outputTokens`：按用户要求，模板均为 `null`，不设置本地任务时长、调用次数和输出 token 上限；如需限额可在 prepare 前填写正整数。CoThink 主副模型共享每任务的时间和调用额度。没有累计输入 16 万 tokens 的隐藏停止门槛。
- `budgets`：分别填写两个模型的 `currency`、`limit`、`inputPerMillion`、`outputPerMillion`。`limit:null` 表示不设本地金额上限；每百万 token 的价格上界仍需填写，用于记录费用，不是实际账单。OpenRouter 使用 USD；Moonshot CN 可使用 CNY。使用开跑时核实的价格上界，不能把目录估价当成真实账单。
- `execution`：固定镜像摘要、断网和资源限制。默认复用项目的固定 Node 镜像，每个工作容器限制 512 MiB、1 CPU、128 PIDs。Docker 镜像必须事先已在本机，run 不临时拉取。

每次实际 HTTP 尝试都先记录发送意图。金额无上限时不做资金预留，收到可靠用量后按配置价格计账；没有可靠用量的费用保持未知。显式设置金额上限时才启用完整上下文的保守预留：三道题每个模型最多六条并发通道，预留可能远大于实际花费，余额不足时不发送。CoThink 内部请求及重试也计入实际请求与费用，不能将未知费用写成零。

本工具的金额是按配置价格上界计账，不是服务商账单。需在各轮预算内累计考虑实际资金余额；不会重置或挪用旧 coding 测试账本，也不会替用户充值。

## 每轮操作

题目文件采用 UTF-8，一行一题，例如 `work/visual-bench/tasks.txt`：

```text
自行车骑鹈鹕
秦始皇骑北极熊
北极熊骑秦始皇
```

准备轮次，不产生模型请求：

```sh
node scripts/visual-bench.mjs prepare \
  --tasks work/visual-bench/tasks.txt \
  --config work/visual-bench/config.json \
  --out work/visual-bench/runs/round-001
```

输出本轮的完整任务文本、组数、限额和版本。运行真实测试时执行：

```sh
node scripts/visual-bench.mjs run --round work/visual-bench/runs/round-001
```

此命令会调用模型并可能产生费用。初始化所有尝试后同时放行；CoThink 的内部成员可继续参与，因此同时进行的物理请求最多可超过九个。服务商是否限流无法由脚本保证。Ctrl+C 取消当前整轮，保留日志、用量和已经产生的内容。

打开盲选页面：

```sh
node scripts/visual-bench.mjs view --round work/visual-bench/runs/round-001
```

盲选页面的可见区域随实际浏览器窗口调整；缩小窗口仍可滚到最后一题和底部操作，不固定模拟1440×1000页面视口。初始窗口大小仅作为打开时的尺寸。

关闭盲选标签页、窗口或退出专用浏览器时，会关闭该轮查看器的浏览器与本地服务；再次执行 view 可重新打开，已保存的选票和结果保留。它不关闭日常使用的 Chrome，也不取消独立运行的模型测试。

每题独立随机排列 A／B／C，刷新和重开不会重新洗牌。可重播、放大动态 HTML，选一个或多个并列最佳，或选择“都不合格”，并填写理由。选择自动存盘，全部完成后才能揭晓。揭晓后记录锁定，显示模型映射、实际成员、状态、耗时、请求与费用上界；报告同时保存为本轮的 `report.json`。

```sh
node scripts/visual-bench.mjs report --round work/visual-bench/runs/round-001
node scripts/visual-bench.mjs summary --runs work/visual-bench/runs
```

summary 仅汇总已揭晓轮次，并分别列出版本、模型、限制、独胜／并列最佳／全不合格数量，不跨配置伪造统一排名。未揭晓轮次不会提前暴露模型映射。

## 隔离、失败和重复运行

- 每个尝试有新进程、新 SDK 会话、新私有数据目录、新空白 HTML 工程。父目录指令、个人 Skills、历史聊天和往轮文件不进入上下文。运行目录与模型可以读取的源码投影分开。
- 三组初始用户消息字节相同。模型 API 网络请求只由宿主中转，工作容器没有网络；中转按任务和模型限制路由，只按下节的明确临时拒绝策略重试；CoThink／Pi SDK 自身的自动重试仍关闭。
- prepare 保存提示词、模型目录、限额及源码／提示词／锁文件指纹。目录与配置不可覆盖；代码或配置变化需 prepare 新轮次。凭据不写入轮次清单。
- 已完成、失败和取消的尝试不自动重跑。再次 run 已结束轮次不发送请求。中断、遗留运行锁或未知任务拒绝恢复发送，先检查原记录；想重测时使用新轮次，旧结果保留。
- 收集正式交付的 HTML 工程，或最终答复中唯一可识别的 HTML 代码块。多个 HTML 入口时优先约定俗成的 `index.html`，否则只有唯一入口才展示；不从多个方案中挑最好的一张，不替模型修复。
- 未形成最终 HTML 的情况在盲选页明确显示，原始 SDK 会话、请求、草稿和错误仍在对应 attempt 目录。视觉检查是用户的判断；空正式检查策略不称为代码已经验证通过。
- 页面自身在揭晓前不发送模型映射、日志或费用。作品原样保留，风格或模型自行署名仍可能让人推测身份；本工具不承诺对抗主动检查本机私有映射文件的用户，也不暗中删除作品文字。
- 不能清除模型已有训练知识，也不能控制服务商内部缓存。能保证的是本地没有传入旧测试记录、评分或成果。

## 临时服务拒绝的重试策略（2026-10-27 用户修订）

只在**完整收到结构化错误响应**、并且没有任何生成结果或用量迹象时，识别以下临时拒绝：HTTP 429 的 `engine_overloaded_error`／明确限流，以及 HTTP 503 的明确过载或暂时不可用错误。仅有状态码、无明确原因的错误、账号配额/余额/认证错误、被截断的错误正文均不触发自动重试。HTTP 200 流中的错误、已有输出、连接中断或缺少确定结束标志不重发。

优先按 `Retry-After` 的秒数或 HTTP 日期等待，并增加少量正向随机偏移，不早于服务商要求。没有有效提示时采用 20、40、80 秒，之后每次 120 秒的基础退避，再增加最多 5 秒的正向随机偏移。没有重试次数或总等待时长上限；可在运行终端按 Ctrl+C 停止，等待和在途请求都会被取消。显式配置的非空限额仍有效。

重试保持原模型、路由、消息和参数不变，在同一 SDK 请求内部完成。每个实际 HTTP 尝试有独立记录，关联同一个逻辑请求及请求内容哈希，保存错误正文、请求ID、限流头、计划/实际等待时间、用量和未知费用。成功作品不重生成，不从多次生成中挑选最佳。一个任务等待不阻塞其他任务。

运行页面显示“服务过载或限流，正在等待重试”和最近计划重试时间，自动刷新总体进度，揭晓前不显示模型对应关系。报告区分总耗时、退避等待时间及其余执行时间（含模型调用、工具和处理），不把其余执行时间称为纯模型生成时间；同一任务的并行成员等待按时间区间合并，不重复相加。

该修订不追溯补跑旧轮次。已结束或中断的轮次仍保留原记录；新版本需 prepare 新轮次。当前暂停的九任务测试须由用户另行明确启动。

## 长流日志与中断排查

请求开始时写入元数据快照，收到的服务商事件逐条脱敏追加到 `home/requests/<请求ID>.events.jsonl`，每条落盘后再读取下一片段。请求结束时写入包含全部事件的完整 JSON 快照；不再为每个片段重写整个历史。新日志与旧版独立 JSON 均可读取。

进程中断后，历史读取会恢复日志中完整的行和可识别的文本片段；最后一行未写完时保留原文件并标注截断。中间行损坏、序号异常或归属不符会明确报错。恢复内容不代表请求完成，也不会恢复发送或推断未知用量。只要最终完整快照已成功保存，即使事件日志不在，仍能读取完整请求。

请求记录中的 `transport` 保存允许记录的响应头、首末收流时间、字节／片段数、原始异常及 cause、SSE 错误和取消来源；中转的每次物理请求在 `ledger.json` 中保存对应诊断。字节数指应用读取的响应体，不是网络链路上的压缩字节数。SSE 诊断副本有长度上限，超出会标注；转发内容不变。诊断不能追溯找回旧记录缺失的异常，也不能单凭一个连接错误判断是哪一层主动断开。

中转以完整 SSE 事件中的 `[DONE]` 为应用层结束标记：先持久化结束状态和用量，再把最后片段交给 SDK。SDK 随后的正常关闭不降级为断流，也不必等待上游 HTTP EOF。结束标记可能跨网络片段，只有完整事件才生效；没有结束标记、标记未完整传输或流内错误仍为未知，不自动重发。缺失用量仍保持费用未知，沿用既有预算政策。诊断中的 `completionSource` 区分 SSE 结束与无标记的 HTTP EOF；主动结束剩余响应体时 `bodyComplete:false` 不等于模型结果未知，应结合 `terminal` 和账本状态阅读。

## 免费验证

```sh
npm run test:visual
```

测试通过 localhost 固定回复和真实 Pi SDK 跑九个独立任务；其中三个 CoThink 任务实际委派、收集和接纳，并在真实 Docker 容器验证网络关闭。浏览器检查验证动画、外部请求／导航阻断、匿名数据、选择持久化、揭晓和报告；另验证明确过载／限流重试、独立任务继续、等待取消、部分输出或未知传输不重发、重试请求内容一致，以及并行等待时间不重复计入墙钟。正常完成但缺少用量时费用保持未知；开启金额限制时保留预留并停止新请求。

这些是运行机制证据，不是模型画图能力或真实服务商并发限流的验证。不要把 fixture 作品当成实际模型成绩。

### 委派题意与最终审查（2026-10-28 本地实现）

新委派先由成员在只读上下文理解宿主提供的原题，成功后接收主模型的 assignment 与 implementationAdvice；首次委派通常至少增加一次请求，计入同一任务账本。成员报告题意冲突后暂停，保留草稿，收到具体更正且自行确认后才恢复。

最终集成截图改交相同主模型的独立短上下文，顺序替换原有最终看图调用，不继承委派解释或成员自评。审查给出观察、理由和 match/mismatch/uncertain；只有匹配判断与版本、实际图像请求、运行检查均有效才可完整交付。具体缺陷可触发修订和新版本复验，缺视野可补拍；没有新证据则保留部分结果。接纳保存、图像发送、请求完成与模型判断是不同事实。

本地 fixture 只验证来源隔离、冲突分支、真实 PNG 传递及版本绑定，不证明模型会识别骑乘关系，也不证明语义或审美提升。旧轮次及其结果不回写；下一次真实测试需另行授权并在冻结源码副本中进行。
